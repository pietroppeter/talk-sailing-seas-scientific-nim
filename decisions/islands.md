# The voyage and its islands

Status: accepted · Updated 2026-11-25

## Context

The submitted description promises an intro, seven islands and a conclusion. This record says what each part must show and why the voyage has its shape; the slide by slide plan is [outline.md](../outline.md).

## Decision

### The shape

- **Order.** Opening (title, about me); Intro; Performance; Science; Ecosystem; Interoperability; Expressivity; Interactivity; Notebook; Conclusion; Thank you.
- **Names and order** (Pietro, 2026-10-27; names again 2026-11-25): short names, for the map and the agenda bar: Performance (slide 2.2 still says "no ceiling"), Science, Ecosystem, Interoperability, Expressivity, Interactivity, Notebook; Interoperability comes before Expressivity. The names are in `islandnames.nim`, the one place to change them. Files and slide IDs follow the new numbers (`slides/island4_interop.nim`, `slides/island5_*.nim`).
- **Travel metaphor as the spine**: a map slide at the start of each island shows progress and keeps the audience oriented.
- **Vertical sections** (Pietro, 2026-10-26): the top row of the deck is the voyage (opening, intro, islands, conclusion, thank you), each section's slides are below its map slide, so a section is easy to skip or shorten on stage.
- **Time per island**: Ecosystem gets the most (3.5 min), since a PyData audience judges it hardest; Island 1 the least (1 min, one slide: Pietro, 2026-11-24, performance is a given), performance is not the speaker's main interest and depth is in Mamy's talk; Science 2.5 min for three stories, told, not demoed.

### What each part shows

- **Intro** (2026-11-24): why there are so many languages in scientific computing, as a table of what each language came to do and its price (Fortran, C, C++, Python, R, Julia, then Nim with "?"); Nim's own tradeoffs as *you get* and *you pay*; and how to read the voyage: seven islands, rocks ahead, deep dives. The two-language problem is named by the speaker, not given a slide.
- **Island 1, Performance** (Pietro, 2026-11-24): one slide, "Reads like Python, runs like C": one sentence on what the Vandermonde matrix is (Pietro: no slide of its own; formula, uses and references in the deep dive), then the Vandermonde matrix written with for loops in Python and in Nim side by side, and a mini benchmark against the Python loops and NumPy (the case study of Jeff Bezanson's thesis behind Julia). The point, said by the speaker: in Nim you are allowed to write for loops. A pointer in orange to "no ceiling" (down to assembly when you need it); Mamy's talk is named in the speaker notes only (Pietro). The benchmark is reproducible (`bench/vandermonde/run.sh`), with its code and caveats in a deep dive.
- **Island 2, Science** (Pietro, 2026-10-27): competent people did science with Nim: Nim in bioinformatics, started by Brent Pedersen and followed by others (Pietro, 2026-11-24: the slide is about the field, not only the person), Vindaar (Sebastian Schmidt) in experimental physics, and QEX, the lattice QCD framework by James Osborn and Xiao-Yong Jin at Argonne (Pietro, 2026-10-28), theoretical physics, a team and a framework rather than one person, the most active scientific Nim project since 2024. Success means using Nim to advance science; slides stay on the science, the libraries Vindaar built get a line (Island 3 covers them). Deep dives go further, plus one on success stories beyond science.
- **Island 3, Ecosystem** (Pietro, 2026-10-27 and 2026-10-28): Arraymancer, Datamancer and ggplotnim as the Nim mirror of NumPy, pandas/dplyr and matplotlib/ggplot2, after Jake VanderPlas's Python Data Science Handbook, through the penguins dataset (seaborn's CSV; the penguins slide shows Allison Horst's whole artwork). Bottom-up: tensors, dataframes built on tensors, plots built on dataframes. The tensor slide shows NumPy-like tensors and linear algebra, not the penguins. Arraymancer is presented as "a solid ndarray with linear algebra, a compact deep learning framework, and the seeds of scikit-learn", with the maintenance facts (last release October 2024) in the speaker notes. Rocks ahead (Pietro): classic ML is only seeds, multiple tensor libraries, an ecosystem that depends on a few contributors.
- **Island 3, the redo** (Pietro, 2026-11-24: add nanuq and tabelline, more on Arraymancer): a second Arraymancer slide on deep learning, a small network written with the `network` macro that learns the penguin species when the deck is built (trained on half, checked on the other half), with lucidrains' GPT-2-like transformers (October 2026) in one line; then the new blocks, Pietro's own: nanuq (Polars for Nim, the same query as the Datamancer slide, Polars style) and tabelline (Great Tables for Nim, a penguin table with a boxplot nanoplot, from the nanuq frame). The stack table gets a Tables row and lists Polars and nanuq beside pandas and Datamancer. Both libraries are said to be weeks old and mostly AI-written, in the speaker notes and in rocks ahead ("they need users"), as for nimlang-pypi and naffprop in Island 4. nanuq and tabelline get their own deep dive (`deepdive/penguins_polars.nim`); the network is also explained step by step in the penguins deep dive.
- **Island 4, Interoperability** (Pietro, 2026-11-24, rethought from scratch): two messages. First, the small ecosystem is not a problem because Nim reaches bigger ones: C, C++ and JavaScript natively (`importc`, `importcpp`, `importjs`), Python, R and Julia through bridges (nimpy, rnim, nimjl, with their maturity said plainly), each with a micro example in three columns on a slide of its own, and a second slide for the other direction, Nim called from Python, R and Julia (Pietro, 2026-11-24). Second, Nim can be the language where you write the fast algorithm and other languages use it: nimlang-pypi (Pietro's package that ships Nim in a Python wheel, installed with `uv add nimlang`; called nimlang-pypi because "nimlang" alone is ambiguous, Pietro 2026-11-24) shown as a recorded terminal session, and naffprop (Pietro's affinity propagation package for Python, written in Nim) as the real example. Both projects are Pietro's, from 2026 and mostly AI-written: said in the deep dive and the speaker notes. The nimlang-pypi slide says it builds wheels, so users need no Nim compiler (as Rust with maturin), and the deep dive compares with the far more mature Rust ecosystem (PyO3, maturin); the naffprop slide shows its interactive figure live beside the code (Pietro, 2026-11-24). The C call runs when the deck is built (`slides/island4_bessel.nim`); the Python sessions are recorded, not live.
- **Island 5, Expressivity** (Pietro, 2026-10-27): custom operators as the easy feature, with hand-written geometry (points, lines, planes, join and meet; `Vec` is a `distinct Point`), and metaprogramming as the advanced one, with Vindaar's unchained (Kepler's third law with `declareUnits` for solar and earth masses). The new units live in `slides/island5_units.nim` and only `SolarMass`, `Msun`, `EarthMass`, `Mearth` are exported to the deck, since `declareUnits` also regenerates the compound SI types.
- **Island 6, Interactivity**: Nim compiled to JavaScript with a snappy port of a fun Shiny app, and an honest note that notebook-style interactivity (Jupyter, Marimo) is not there yet.
- **Island 6 app** (Pietro, 2026-11-24): the plant app, Nick Strayer's Shiny for Python app that Pietro first ported in nblog, contrasted with the original running in the browser with shinylive (offline, exported into `docs/shiny/` by the build, not committed). The Nim port uses Karax (its `buildHtml` code is shown on the slide, Pietro asked for it) and a canvas bound with importjs; the slide (a secret easter egg, no visual hint; `-d:dragVariant=false` for the plain one) and the deep dive make the slider lines of that code draggable with zogyn, Pietro's declarative dragging library, the app's sliders following (a trick after Bret Victor's Inventing on Principle, explained in the deep dive, not on the slide; both are dependencies in `atlas.lock`); the curve is a module that runs on both backends (the deep dive also plots it with ggplotnim). Rocks ahead is the REPL: experiments only, and a REPL fits a statically typed, ahead-of-time compiled language badly.
- **Island 7, Notebook**: literate programming and computing, which Jupyter made central, and nimib, the Nim option that goes in an unexpected direction, with at least one of its limitations. The unexpected direction (2026-11-24): no kernel, the notebook is a plain Nim program you run, top to bottom, and running it writes the page. The nimib slide shows a tiny document and what it renders side by side, the right side really rendered from the left when the deck is built (`nimibCode`); a slide lists what you can make with it (pages, slides, books, interactive pages, READMEs, your own blocks), all used by this talk; rocks ahead: no kernel (every change reruns everything), made to explain more than to explore, a small community. The running example is the distance of the horizon from the deck of a boat (one nod to the sea). Deep dive `notebook` (not `nimib`: a module cannot share the name of the package it imports).
- **Conclusion**: one takeaway for the beginner, one for the builder, your language seen from Nim (K4: what each mainland language looks like after the voyage, pointing back to the islands), why Nim is still niche, and an opinionated view of the language, the ecosystem, the community and the governance; the builder's slide gathers the rocks ahead of the islands.
- **Thank you** (Pietro, 2026-10-26): an animation in Nim with p5nim (a small show of the JavaScript backend, K2): a grid of points flies along curves into "Thank You!" and "Questions?" and back, in a loop, after a sketch by Okazz (CC BY-NC-SA 3.0, like the slide's code; the rest of the repo is MIT). It stays on screen during Q&A, last on the top row; it builds on its own too (`docs/thank_you.html`).

## Options considered

- A plain agenda slide instead of the map: the abstract already sells the voyage.
- One flat row of slides instead of vertical sections.
- Island 2: two shapes of success (toolmaker vs scientist) or a timeline of the pioneers, set aside to keep it about science; QEX as a line in Island 3 instead of a story, set aside since QEX is science.
- Island 3: nimpy with pandas, set aside since the island is about Nim's own stack; nanuq and tabelline on one slide (the query and the table together), kept apart so each library shows its own code; "more than an ndarray" for Arraymancer, set aside because it reads as parity with PyTorch.
- Island 4: wrapping a bigger C library on the slide (one function makes the point; c2nim and Futhark are in the deep dive); a live `uv add nimlang` (no live demos).
- Island 5: hand-written physical units for the easy example (a repeat of the second); a sailing theme for the examples (dropped: enough sea already).
- Thank you: straight moves with easing, or bursting into big circles (Pietro chose curves); a separate "Questions?" slide; a static slide with links.

## Consequences

- Three stories in 2.5 minutes: about 30 seconds each; any story's code can be skipped on stage, the deep dives carry the depth.
- Five content slides in Island 4: islands average 3 minutes and some go faster; exact timing comes with the dry run (Pietro, 2026-11-24).
- Five content slides in Island 5's 2.5 minutes: each example is two quick slides; the line-meets-plane slide or the units declaration can be dropped if rehearsal runs long.
- The animation only draws while its slide is shown and uses no network; check it on the presentation laptop.
