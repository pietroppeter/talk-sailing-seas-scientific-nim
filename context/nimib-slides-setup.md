# Jumpstarting a nimib + nimiSlides talk

Context gathered on 2026-10-04 from Pietro's past talk repos, to bootstrap the
slides for "Sailing Seas of Scientific Nim" (Compute Paris 2026).
Nothing is scaffolded yet: this file only describes the setup to copy.

## TL;DR

- Most recent nimiSlides talk: [pietroppeter/hola-talk](https://github.com/pietroppeter/hola-talk)
  (Nov 2025, Agile Nomads, Fuerteventura). It is the template to copy:
  `atlas` for deps, a `slides/` folder with `my.nim` + `index.nim`.
- **Big change since then**: nimib **v0.4.0/0.4.1** (May–June 2026) rewrote the
  block/rendering backend (no more mustache), and nimiSlides **v0.4.0**
  (July 2026) was ported to it and now `requires "nimib >= 0.4.1"`.
  The current `my.nim` uses the old 0.3 APIs (`nb.partials`, `nb.renderPlans`,
  `newNbSlimBlock`, `nb.blk.context`) and **will not compile against the latest
  versions**. Either port `my.nim` (recommended, see below) or pin the old versions.
- Publishing has always been: commit the generated `.html` next to the `.nim`
  and serve the repo with GitHub Pages from the default branch (no CI workflow).

## hola-talk layout (the one to copy)

```
hola-talk.nimble      # requires "nimiSlides"
nim.cfg               # Atlas-generated --path entries into deps/
.gitignore            # deps
README.md             # title, abstract, bio, setup notes
slides/
  my.nim              # helpers + theme, also a test deck when run directly
  my.html
  index.nim           # the talk
  index.html
  images/logo-agilelab.png
```

`hola-talk.nimble` is just one line: `requires "nimiSlides"`.

`nim.cfg` (generated by `atlas install`):

```
############# begin Atlas config section ##########
--noNimblePath
--path:"deps/nimiSlides/src"
--path:"deps/nimib/src"
--path:"deps/parsetoml/src"
--path:"deps/mustache/src"
--path:"deps/markdown/src"
--path:"deps/jsony/src"
--path:"deps/fusion/src"
############# end Atlas config section   ##########
```

README note from hola-talk: "this repo uses atlas. if you have a recent nim
installation (grab it with grabnim) you should be able to make it work with
`atlas install`" (it was his first time with atlas + grabnim).

Build: `nim r slides/index.nim` (and `nim r slides/my.nim` for the test deck).
The html lands next to the source.

## What my.nim provides (hola-talk version, identical to domain-driven-data-science)

- AgileLab palette constants: `agileLightBlue #02A4BD`, `agileDarkBlue #0e1f53`,
  `agileWhite`, `witboostOrange #ee961a`.
- `agileTheme()`: `setSlidesTheme(Black)` + CSS variables (dark blue background,
  white text, light blue links), left-aligned lists.
- `nbTextSmall` (text wrapped in `<small>`) and `reference` (alias, used for the
  repo link on the title slide).
- `nbImg(url, width, caption, alt)`: image block with explicit width.
- `myInit(sourceFileRel)`: `nbInit(theme=revealTheme)`, `nb.useLatex`, theme,
  `strong` in light blue / `em` in orange (bold, non-italic), an alias
  `nimibCodeAnimate` for `animateCode`, and an AgileLab logo fixed bottom-left by
  overriding the `document` partial.
- `testSlide` + `when isMainModule` so `my.nim` renders a style-check deck.

Talk modules follow the pattern: `template xxxSlide* = slide: ...`,
then `template presentation* = titleSlide; ...` and
`when isMainModule: myInit("index.nim"); presentation; nbSave`.
Bigger talks put each section in its own module imported by `index.nim`.

## Porting my.nim to nimib 0.4 / nimiSlides 0.4

What still works unchanged: `nbInit(theme = revealTheme)`, `nb.useLatex`,
`setSlidesTheme`, `nb.addStyle`, `nbText`, `nbRawHtml`, `slide`, `speakerNote`,
`columns`/`column`, `fragment*`, `animateCode`, `cornerImage`, `footer`.

What needs rewriting (sketch, **not compiled yet**, based on the nimib 0.4
changelog and nimiSlides' `NbBigText`):

```nim
# nbTextSmall: subclass NbText, reuse the nbText partial
newNbBlock(NbTextSmall of NbText):
  toHtml:
    "<small>" & nb.renderPartial("nbText", jsonutils.toJson(blk)) & "</small>"

template nbTextSmall*(ttext: string) =
  nb.add newNbTextSmall(text = ttext)

# nbImg: real fields instead of a mustache context
newNbBlock(NbImg):
  url: string
  width: string
  caption: string
  alt: string
  toHtml:
    &"""<figure>
<img src="{blk.url}" alt="{blk.alt}" width="{blk.width}">
<figcaption>{blk.caption}</figcaption>
</figure>"""

template nbImg*(url: string, width: string, caption = "", alt = "") =
  let blk = newNbImg()
  blk.url = nb.doc.relToRoot(url)
  blk.width = width
  blk.caption = caption
  blk.alt = if alt.len == 0: caption else: alt
  nb.add blk
```

- `addNbTextSmall` / `addNbImg` disappear (registration happens in `newNbBlock`).
- The `nimibCodeAnimate` alias was a workaround for 0.3 render plans; probably
  not needed anymore (`animateCode` is its own `NbAnimateCode` block).
- Logo: the `document` partial no longer exists; the doc is rendered by
  `nb.backend.funcs["NbDoc"]` (`revealNbDocToHtml`). Simplest options are
  `cornerImage(..., LowerLeft)` per slide via a wrapper template, or `footer`
  with raw html; or override the `NbDoc` func with a copy that appends the logo.
- `nb.partials[...]` → `nb.backend.partials[...]`, and partials are now Nim
  funcs `(blk: JsonNode, nb: Nb): string` instead of strings.

Fallback if porting gets in the way: `requires "nimib == 0.3.12"` and
`requires "nimiSlides == 0.2.6"` and reuse `my.nim` as is.

Recommendation: go with 0.4. A talk about scientific Nim given by nimib's
author is a good showcase for the new version, and nimiSlides' own
`nimconf2026.nim` is a working example of 0.4-style custom blocks.

## Publishing

- Past talks: html committed, GitHub Pages serving the default branch root,
  e.g. https://pietroppeter.github.io/nim-for-pythonistas/ and
  https://pietroppeter.github.io/ai-a-blast-from-the-past/ (`.nojekyll` added).
- With hola-talk's `slides/` folder the URL becomes `.../<repo>/slides/`.
  Alternative: keep sources in root, or add an `index.html` redirect.
- No GitHub Actions in his talk repos; nimiSlides itself builds docs in CI
  with `iffy/install-nim` + `peaceiris/actions-gh-pages` if that is ever wanted.
- reveal.js 5.0.4 is loaded from cdnjs by default; `nimib.toml` can set
  `[nimislides] localReveal = "path"` for offline presenting (worth doing for a
  conference venue with flaky wifi).
