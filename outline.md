# Outline

The living plan of the talk: sections, timing and slides (`<section>.<slide>` IDs, used by the slide files). Updated in place; decisions behind it are in [decisions/](decisions/).

## Narrative Arc

The talk is a sea voyage. From a boat you only get a very limited view of the land: we will not go in depth anywhere, and the audience gets the feeling of each island rather than a tour of it. We leave the familiar mainland of scientific computing (Fortran, C, C++, R, Python, Julia) noting that each language came with its own tradeoffs and promising to show Nim's (K1: Nim's tradeoffs as a scientific computing language, and its untapped potential). We then hop across seven islands, and together they show Nim's strengths (K2: easy like Python, fast as C, with superpowers: metaprogramming, the JavaScript backend and interop), while the success stories and the data stack show it holds up in real work (K3: pragmatic, Nim is ready for more). Where it fits, an island ends with an honest "rocks ahead" line on where Nim falls short, so the pitfalls add up along the way (K3). We touch back land in the conclusion with one takeaway for the beginner, one for the builder, and an opinionated look at why Nim is still niche despite being stable and ready for more (K3), closing K1: why it is fun, exciting, and has more potential than the impact it had so far. Throughout, comparisons with the audience's languages are framed as tradeoffs, not as a contest, so people leave appreciating their own language and the diversity of languages better (K4: appreciate the diversity of languages).

K1-K4 are the key messages in [decisions/tone.md](decisions/tone.md). Why the outline is shaped this way is in [decisions/islands.md](decisions/islands.md).

### 5. Island 4: Interoperability (~3 min)

Two messages (Pietro, 2026-11-24): Nim's small ecosystem is not a problem, because Nim reaches the bigger ones (C, C++ and JavaScript natively, Python, R and Julia through bridges); and Nim can be the language where you write the fast algorithm that other languages use. Carries K2 (interop superpower) and K3. Deep dive: `deepdive/interoperability.nim`.

5.1 **Island 4** - section title on the map.
5.2 **Small ecosystem, big neighbours** - natively C, C++, JavaScript with `importc`, `importcpp`, `importjs`: C's Bessel function `j0` declared in one line and called when the slide is built; through bridges Python, R, Julia (next slide); link to the deep dive [example].
5.3 **Bridges: Nim calls Python, R, Julia** - three columns, one micro example each from the libraries' READMEs (shown, not run): nimpy calls numpy's `mean`, rnim R's `sum`, nimjl Julia's `sqrt`; rnim is a prototype, nimjl needs Julia [example].
5.4 **Bridges, the other way: Nim inside** - the same three columns the other way, a Nim `add` compiled as a library and called: nimpy's `exportpy` from Python, rnim's `exportR` from R (with the R wrapper rnim writes), the C ABI (`exportc, dynlib`) from Julia's `ccall` [example].
5.5 **Write it in Nim, use it from Python** - `nimlang-pypi`, installed with `uv add nimlang` (the Nim compiler in a Python wheel, `zig cc` as C compiler): `fib` in Nim with nimpy's `exportpy`, then a recorded terminal session that builds it and times it against `slow.py` (95.8 ms vs 11.5 ms); it also builds the wheels, so Python users of a Nim-powered library need no Nim compiler, as Rust does with maturin [example].
5.6 **A real package: naffprop** - affinity propagation with R's apcluster features behind scikit-learn's API, the algorithm in Nim, built with nimlang-pypi, wheels for five platforms, 1.1 to 2.9 times faster than scikit-learn [example]; on the right, live in an iframe, its interactive figure "How exemplars emerge" (the same Nim compiled to JavaScript, vendored in `docs/assets/naffprop/` by `scripts/vendor-assets.sh`).
5.7 **Rocks ahead** - bridges of different maturity (nimpy solid, rnim a prototype, nimjl needs Julia); no maintained packaging tool for years, `nimlang-pypi` new and alpha; few Python users know Nim, compared with Rust.

### 6. Island 5: Expressivity (~2.5 min)

Two language features that make Nim good for scientific use: custom operators written by hand, then units and their operators generated by macros, inspired by Vindaar's unchained library. Carries K2 (metaprogramming superpower).

6.1 **Island 5** - section title on the map.
6.2 **Custom Operators: defined** - "You can define custom operators easily in Nim, as a normal function, using backticks"; hand-written geometry: `Line` and `Plane` types over `Point` and `Vec` (a `distinct Point`), `+` joins (two points make a line, a line and a point a plane), `*` meets (a line hits a plane in a point); `Point + Point` is not a point, so the types let it mean the line through them [example].
6.3 **Custom Operators: applied** - "A line is defined by two points, a plane is defined by three points, they generically intersect in one point": the `pt` constructor, the line, the plane and their meet [example]; the slide links its explainer.
6.4 **Macros to define Units** - Vindaar's unchained: units checked at compile time, plain floats at run time; its `declareUnits` macro declares the SI units (left column: Gram and Meter, read from unchained's si_units.nim at build time) and adds the solar mass and the Earth mass (right column), and the macro writes the types, aliases and conversions while `*`, `/` and `+` are macros that work out the unit of the result.
6.5 **Units applied** - Kepler's third law: `period(a, mass)` is `2 * PI * sqrt(a^3 / (G_Newton * mass))` for any length and any mass: the year of Mars (1.524 AU around one solar mass) and the month of the Moon (384 400 km around one Earth mass); adding a length to a mass does not compile [example]; the slide links its explainer.
6.6 **⚠️ Rocks ahead 🪨** - (Claude's proposal, dry run 1) macros are hard to write and hard to debug (errors in generated code); every DSL is a new little language for its readers; with great power: procs and templates first.

### 9. Conclusion: back on land (~2.5 min)

Takeaways and an opinionated reflection on why Nim is still niche. Carries K1, K3 and K4. The thank-you slide is not part of the conclusion's vertical stack: it is the last slide of the top row, after it.

9.1 **Back on land** - the map with all seven islands visited.
9.2 **For the beginner** - lede "Try it: accessible, fun, and a mirror for your own language"; reads like Python, with a compiler that checks your types; where to start (the playground, Nim for Python programmers, Exercism, SciNim getting started); a first project (an Advent of Code puzzle, a small CLI, a nimib page).
9.3 **For the builder** - two columns: *Fair winds* (prototype and fast code in one language; C and C++ libraries one line away; a Python package with wheels, the browser for free; macros for your own notation) and *Rocks ahead*, the rocks collected on the islands (a tiny ecosystem, you will write more code; a few maintainers carry each library; bridges and packaging of uneven maturity; no REPL, macros can be hard to read).
9.4 **Your language, seen from Nim** - a table "Nim makes you notice", one row per language of the mainland, each pointing back to an island: Python (loops are slow, so you think in arrays; Island 1), R (dplyr's formulas are metaprogramming, like Datamancer's `f{...}`; Island 3), Julia (the JIT gives a REPL and costs a warm-up; Island 6), C and C++ (the same machine code with less ceremony, macros instead of templates and the preprocessor; Island 5). Lede: not "switch to Nim": every language is a set of tradeoffs, and their diversity is how scientific computing explores them (K4).
9.5 **Why still niche?** - Pietro's opinionated view as a table: language (stable, 1.0 in 2019, 2.0 in 2023, ready for more), ecosystem (small, libraries depend on a few people), community (friendly and small, one person can make a difference), governance (highlighted: the main shortcoming, few people decide and the direction is hard to read from outside), tooling (editor support and compile times behind Rust's, Nimony and NIF the way to catch up). Closing lede (K1): fun, exciting, and with more potential than the impact it had so far.
9.6 **Thank you** - the last slide of the top row, after the conclusion stack. An animation written in Nim with p5nim and compiled to JavaScript: a grid of colored points flies along curves into the words "Thank You!", one color per letter, back into the grid, then into "Questions?" and back, in a loop, based on a sketch by Okazz (the footer says it is built with p5nim, links a page that explains the code, and credits the sketch by Okazz, CC BY-NC-SA 3.0); the link to the deck is above the footer.
